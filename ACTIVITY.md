# Активность подписчиков (last seen)

Модуль `tg_activity.py` встроен в трекер: тот же процесс, та же SQLite (`DB_PATH`), тот же Google-файл.

## Почему «накопление», а не снимок
Telegram отдаёт список подписчиков канала примерно по ~200 человек. Поэтому:
1. Несколько раз в день (`ACTIVITY_SCAN_HOURS`, по умолчанию 6) читаем это «окно» (свежие подписчики) и
   сохраняем для каждого user_id и ключ доступа. Каждый новый подписчик попадает в окно, пока он свежий.
2. Раз в сутки (`ACTIVITY_HOUR`, по умолчанию 10:00 по `REPORT_TZ`) перепроверяем last seen у ВСЕХ накопленных
   людей поимённо, в том числе у тех, кто давно вышел из окна.
3. Кто сейчас в канале: последнее событие `join` в таблице `events` ИЛИ человек в текущем окне.
4. Старых людей (вступили до запуска и уже не в окне) добираем по публичному username из `events`
   (`ACTIVITY_BACKFILL_PER_RUN`, по умолчанию 150 за ежедневный запуск; сначала самые свежие). Telegram жёстко
   ограничивает такие запросы (ответ FloodWait на несколько часов): бот запоминает блокировку, не добирает чаще
   раза в 20 часов и повторные `/activity` лимит не тратят. Не поднимайте лимит сильно.
   У кого username нет или он сменился, статус неизвестен. Это видно в `coverage_%`.
5. Источник человека = последняя не-organic ссылка из его событий `join`/`request`; нет событий — `unknown/organic`.

Охват растёт со временем: сразу видны свежие и те, у кого есть username, дальше добираются остальные,
а все новые вступившие ловятся окном.

## Вкладки Google-файла (модуль ставит их первыми и оформляет сам)
- `How to read` — инструкция внутри файла (английский, для команды).
- `Cohorts` — одна вкладка: ссылка × неделя вступления. Видны главные колонки: `Joined`, `★ Subscribed & active % (main metric)`
  (North Star), `★ Change vs previous (pp)` (к предыдущей надёжной неделе той же ссылки, зелёный/красный),
  `Can I trust this row?` (`Reliable` / `Too early` / `Not enough data`, ненадёжные строки серые). Детали
  (`Still subscribed`, `Didn't leave in first 7 days %`, `Activity checked %`, `Active last 7/30 days %`) свёрнуты
  под «+» над колонками. Фильтр, закрепление, подсказки на заголовках. Перезаписывается целиком при каждом запуске.
  Вкладку `Summary` больше не пишем, её можно удалить.
- `Activity Channels`, `Activity Sources` — подробности по дням (история копится, строки дня без дублей).
- Старые вкладки `Activity`, `Activity by Source`, `Activity Cohorts` (прошлые версии) можно удалить.

### North Star: ★ Subscribed & active % (main metric)
Из **всех**, кто вступил по ссылке за неделю, доля тех, кто сейчас подписан **и** был в Telegram за последние 7 дней.
Формула: `Still subscribed % × Active last 7 days %`. Уход людей снижает метрику, и неактивные оставшиеся тоже. Выше = лучше.
Пусто для `Too early` когорт (там Active бессмысленен). Сравнение со средним по каналу убрано: оно не учитывало отписавшихся.

### Почему качество недели видно только через ~2 недели
Человек, вступивший за последние 7 дней, по определению был в Telegram за последние 7 дней: `Active 7d` для свежих
когорт почти всегда ~100% и ничего не говорит. Когорта «созревает», когда с понедельника её недели прошло 14 дней
(`MATURE_AFTER_DAYS`); до этого строка помечена `Too fresh`. Быстрый честный сигнал — `Stayed 7d %`: вышел ли человек
из канала в течение 7 дней после вступления. Он считается по событиям join/leave для всех, без запросов к Telegram.
- `Data quality = OK`: известен статус минимум у `ACTIVITY_MIN_CHECKED` человек (20), охват не ниже
  `ACTIVITY_MIN_COVERAGE` % (50) и когорта созрела. Пороги выбраны произвольно, настраиваются.

## Включение (Railway → Variables)
1. `API_ID`, `API_HASH` — my.telegram.org.
2. `SESSION_STRING` — `python activity_login.py` (в окружении нужны `API_ID`, `API_HASH`). Отдельный
   Telegram-аккаунт, **админ** во всех каналах из `CHANNEL_IDS`.
3. Необязательно: `ACTIVITY_SCAN_HOURS`, `ACTIVITY_HOUR`, `ACTIVITY_WINDOW_DAYS` (в `Activity Sources`
   учитывать вступивших за последние N дней, 0 = за всё время).
4. Без этих переменных модуль выключен, трекер работает как раньше.

Команда админам: `/activity` — скан + перепроверка + запись в Sheets сейчас.

## Как читать
- Смотрите `coverage_%`: низкий охват = мало данных, процентам доверять нельзя.
- Корзины: `online`, `d1`, `d7`, `d30`, `older` (last seen открыт) и `h_recently`, `h_week`, `h_month`, `h_long`
  (скрыт, Telegram даёт только грубую корзину). «Активен 7д» = online, d1, d7, h_recently, h_week;
  «30д» = то же + d30, h_month. Меняется в `tg_activity.py`.
- Если за период канал получил почти 200 новых подписчиков сразу, часть могла не попасть в окно. В логах будет
  предупреждение: уменьшите `ACTIVITY_SCAN_HOURS`.
- В списке «не снято» бот пишет причину по каждому каналу (например, «аккаунт не админ в канале»).
- «Был в Telegram» ≠ «читает канал».

## Исправления по ревью таблицы (ноябрь)
- Оформление вкладки теперь полностью сбрасывается перед применением: числовой формат старой раскладки колонок больше не «прилипает» (счётчик `Still in channel` не показывается как %).
- `active_7d_%_of_joined` в `Activity Sources` пустой, если сейчас в канале больше людей, чем вступило по ссылке (раньше выходило 1980%).
- Запись в Google-файл идёт под замком, после записи удаляются полностью совпавшие строки за этот день (дубли в `TG Joins`).
- При старте бот дописывает в `TG Joins` последние 3 дня (если отчёт не отработал). Пропущенный старый день: `/report 2026-07-31` (шлёт ещё и в Slack).
- Названия каналов добираются повторно перед отчётом: канал, чьё название не определилось на старте, больше не уходит в таблицу как `-100…`.
