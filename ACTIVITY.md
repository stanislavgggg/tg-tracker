# Активность подписчиков (last seen)

Модуль `tg_activity.py` встроен в трекер: тот же процесс, та же SQLite (`DB_PATH`), тот же Google-файл.

## Почему «накопление», а не снимок
Telegram отдаёт список подписчиков канала примерно по ~200 человек. Поэтому:
1. Несколько раз в день (`ACTIVITY_SCAN_HOURS`, по умолчанию 6) читаем это «окно» (свежие подписчики) и
   сохраняем для каждого user_id и ключ доступа. Каждый новый подписчик попадает в окно, пока он свежий.
2. Раз в сутки (`ACTIVITY_HOUR`, по умолчанию 10:00 по `REPORT_TZ`) перепроверяем last seen у ВСЕХ накопленных
   людей поимённо, в том числе у тех, кто давно вышел из окна.
3. Кто сейчас в канале: последнее событие `join` в таблице `events` ИЛИ человек в текущем окне.
4. Старых людей (вступили до запуска и уже не в окне) добираем по публичному username из `events`
   (`ACTIVITY_BACKFILL_PER_RUN`, по умолчанию 150 за ежедневный запуск, из-за лимитов Telegram; сначала самые свежие).
   У кого username нет или он сменился, статус неизвестен. Это видно в `coverage_%`.
5. Источник человека = последняя не-organic ссылка из его событий `join`/`request`; нет событий — `unknown/organic`.

Охват растёт со временем: сразу видны свежие и те, у кого есть username, дальше добираются остальные,
а все новые вступившие ловятся окном.

## Вкладки Google-файла (модуль ставит их первыми и оформляет сам)
- `How to read` — инструкция внутри файла (английский, для команды).
- `Summary` — по каждой ссылке: когорта прошлой недели против когорты этой недели, изменение в п.п. Начинать отсюда.
- `Cohorts` — ссылка × неделя вступления: `Joined`, `Still in channel`, `Status known %`, `Active 7d/30d %`,
  `vs channel avg (pp)` (зелёный = лучше канала, красный = хуже), `Data quality` (`OK` / `Low data`, серые строки).
  Есть фильтр, закрепление, подсказки на заголовках. Перезаписывается целиком при каждом запуске.
- `Activity Channels`, `Activity Sources` — подробности по дням (история копится, строки дня без дублей).
- Старые вкладки `Activity`, `Activity by Source` (первый тестовый запуск) можно удалить.
- `Data quality = OK`, если известен статус минимум у `ACTIVITY_MIN_CHECKED` человек (по умолчанию 20) и охват не ниже
  `ACTIVITY_MIN_COVERAGE` % (по умолчанию 50). Пороги выбраны произвольно, настраиваются.

## Включение (Railway → Variables)
1. `API_ID`, `API_HASH` — my.telegram.org.
2. `SESSION_STRING` — `python activity_login.py` (в окружении нужны `API_ID`, `API_HASH`). Отдельный
   Telegram-аккаунт, **админ** во всех каналах из `CHANNEL_IDS`.
3. Необязательно: `ACTIVITY_SCAN_HOURS`, `ACTIVITY_HOUR`, `ACTIVITY_WINDOW_DAYS` (в `Activity Sources`
   учитывать вступивших за последние N дней, 0 = за всё время).
4. Без этих переменных модуль выключен, трекер работает как раньше.

Команда админам: `/activity` — скан + перепроверка + запись в Sheets сейчас.

## Как читать
- Смотрите `coverage_%`: низкий охват = мало данных, процентам доверять нельзя.
- Корзины: `online`, `d1`, `d7`, `d30`, `older` (last seen открыт) и `h_recently`, `h_week`, `h_month`, `h_long`
  (скрыт, Telegram даёт только грубую корзину). «Активен 7д» = online, d1, d7, h_recently, h_week;
  «30д» = то же + d30, h_month. Меняется в `tg_activity.py`.
- Если за период канал получил почти 200 новых подписчиков сразу, часть могла не попасть в окно. В логах будет
  предупреждение: уменьшите `ACTIVITY_SCAN_HOURS`.
- В списке «не снято» бот пишет причину по каждому каналу (например, «аккаунт не админ в канале»).
- «Был в Telegram» ≠ «читает канал».
